17 — Quickwit (recherche logs / traces sur S3) — mode distribué, tests

Note

Statut : ✅ installé (tests) · Date : 2026-11-11

Objectif

Quickwit : moteur de recherche et d’analyse écrit en Rust (basé sur tantivy), conçu pour les logs et les traces. Les index sont stockés directement sur un stockage objet S3, et les nœuds de recherche n’ont pas d’état. Il fournit une API REST, une API compatible Elasticsearch (_bulk, _search, agrégations), l’ingestion OpenTelemetry (OTLP) et Jaeger, ainsi qu’une interface web.

Option retenue : A — distribué, pour des tests. Les données vont dans Garage et le metastore dans pg-main. La collecte des logs du cluster (OTel Collector + plugin Grafana) n’est pas installée.

Rôle QuickwitNotre système
Stockage des index (splits)Garage S3, s3://quickwit/indexes
Metastore (catalogue des index et des splits)PostgreSQL pg-main, base quickwit, rôle quickwit

Prérequis

  • 07 (pg-main), 09 (Garage), 16 (ServiceMonitor)

Configuration (values/quickwit.yaml.gotmpl) 

config:
  metastore_uri: postgres://quickwit:${QW_PG_PASSWORD}@pg-main-rw.databases.svc:5432/quickwit
  default_index_root_uri: s3://quickwit/indexes
  storage:
    s3:
      flavor: garage
      endpoint: http://garage.garage.svc:3900
      region: garage
      force_path_style_access: true
      checksum_algorithm: disabled      # indispensable avec Garage (voir pièges)

${QW_PG_PASSWORD} est interpolé par Quickwit au démarrage. Ce n’est pas helmfile qui le remplace.

L’Ingress envoie …/ingest et _bulk vers l’indexer, /api/v1/indexes vers le metastore, et tout le reste vers le searcher.

make qw-status                                   # version, nœuds, index
make qw-index-create INDEX=demo-logs             # depuis deploy/k8s/quickwit/indexes/demo-logs.yaml
make qw-demo-logs N=2000                         # logs JSON de démo (scripts/qw-demo-logs.py)
make qw-search Q='level:ERROR AND message:timeout'
make qw-search Q='message:"connection refused" AND service:payment'

Index de test demo-logs : timestamp (datetime, fast), level et service (raw, fast), message (texte, positions pour les phrases), latency_ms (u64, fast), mode dynamique pour les autres champs, rétention de 7 jours.

Ce que cela implique

  • Aucune fonction réservée : contrairement à RisingWave (12) et Redpanda (14), il n’existe ni édition Enterprise, ni clé de licence, ni limite de CPU, de mémoire ou de durée. Tout le code du dépôt est utilisable tel quel.
  • Licence permissive : usage commercial, modification, redistribution et offre en SaaS autorisés, sans obligation de publier ses modifications (contrairement à l’AGPL). Il faut seulement conserver les mentions de licence et de copyright (et le fichier NOTICE s’il existe).
  • ⚠️ Ne pas utiliser d’image 0.8.x : elle reste sous AGPL-3.0. Exposer une version modifiée sur le réseau obligerait alors à publier ses sources. C’est une raison de plus pour forcer image.tag: v0.9.3 (le chart déploie v0.8.2 par défaut).

Pièges rencontrés

  • Invalid payload signature (400) de Garage sur chaque upload de split : par défaut, Quickwit 0.9 demande au SDK AWS un checksum CRC32C envoyé en trailer (aws-chunked), ce que Garage refuse.
    • Les variables AWS_REQUEST_CHECKSUM_CALCULATION=when_required sont ignorées : Quickwit force sa propre configuration du SDK.
    • checksum_algorithm: md5 ne suffit pas : le SDK ajoute toujours son CRC32.
    • ✅ checksum_algorithm: disabled repasse le SDK en WhenRequired. L’intégrité reste couverte par la signature SigV4 (SHA-256 du corps).
    • flavor: garage ne règle que la région et le path-style, pas les checksums.
  • 504 Gateway Time-out sur l’ingestion : avec commit=wait_for, nginx coupe après 60 s si l’indexation échoue en boucle. C’était un symptôme de l’erreur précédente. Les documents restent dans le WAL de l’indexer et sont publiés une fois le problème corrigé : rien n’est perdu.
  • Splits Staged dans le metastore après des uploads ratés (55 ici) : le janitor les supprime automatiquement après un délai de grâce.
  • Metastore : 3 redémarrages au premier déploiement : la base quickwit n’existait pas encore (CNPG crée la base après le rôle). Le problème se résout tout seul.
  • Index otel-logs-v0_9 et otel-traces-v0_9 créés automatiquement : ce sont les index par défaut de l’ingestion OpenTelemetry, prêts pour l’option C.
  • make qw-search avec des guillemets dans la requête : la cible passe Q par variable d’environnement (export Q) pour ne pas casser le shell.

Pour aller plus loin

  • Option C : OpenTelemetry Collector (DaemonSet, filelog → OTLP vers l’indexer) pour les logs de tous les pods, et plugin Grafana Quickwit (AGPL-3.0, voir Licence).
  • Source Kafka : Quickwit peut indexer directement un topic Redpanda (source_type: kafka), par exemple shop-events (15).
  • Montée en charge : searcher.replicaCount, indexer.replicaCount.
